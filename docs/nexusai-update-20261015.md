# NexusAI update candidate — 2026-10-15

## Source and scope

Merge upstream `b76b13379d3b7d67ab0bc424516bb6fd2522bd8e` into the NexusAI
fork descended from `0e2feba1537d848dfd403a5152b0e82a9a9739f5`.
The upstream snapshot contains release v0.7.0 and pooled-embedding LM-head
elimination (`cb55ffe6e`, upstream PR #30445).

Ported behavior:

- `use_slot_prompt` is parsed through the current request schema and prepends
  cached slot tokens to a completion. It defaults to false.
- Continuation requires a populated, explicit slot and a single completion.
  This prevents accidentally continuing another client's automatically selected
  slot. NexusAI already supplies `id_slot`.
- Context checkpoints cannot extend beyond the validated common token prefix.
- The original candidate forced 8 recurrent rollback states. Follow-up hybrid
  tests with short and 8,801-token prefixes passed using upstream's native
  settings, so the GitLab version removes this override from the core.

The old manual checkpoint insertion on restore is superseded by upstream's
checkpoint appendix serialization and validated restore. The previous forced
checkpoint-position arithmetic is also superseded by upstream state handling.
Do not blindly paste the historical restore patch into the new implementation.

## Local validation

CPU compilation: GCC 13.3, OpenSSL 3.0.13. Isolated synthetic tests passed with
`stories260K-f32.gguf` and hybrid `Qwen3.5-0.8B-Q4_K_M.gguf`:

- save, erase, restore and continue with identical deterministic output to a
  fresh complete-prompt request;
- restore after a process restart;
- alternate documents without prefix contamination;
- reject an unpinned or empty continuation slot;
- native streaming and two independent parallel slots;
- OpenAI chat and streaming with the hybrid model's embedded chat template;
- reject corrupted state without terminating the server.

The hybrid continuation evaluated 6 tokens, compared with 282 for the full
prompt. This demonstrates cache reuse, not a general hardware speedup.

Reproduce without accessing a worker service:

```sh
python tests/prompt-cache/regression.py \
  --binary /path/to/new/llama-server \
  --model /path/to/model.gguf --output /private/test-results
```

## Existing slot files

A hybrid slot generated by old build 9426 (`f2ea51234`) was rejected with HTTP
400 by the new build. This does not establish compatibility for the fleet's
other builds. Preserve old binaries and slot files together. Regenerate prompt
caches from their source with the candidate build and use separate filenames;
do not overwrite the only working old cache. Never copy internal KV-state
bytes between versions or treat a failed restore as a successful cache hit.

## Windows candidate and deployment

The original GitHub candidate workflow below was replaced by the generic
GitLab pipeline. See [fork-runtime.md](fork-runtime.md) for current builds,
packages and parameter names. The GitHub candidate pinned to `c0857da049b0`
predates removal of the forced rollback setting and is not the final GitLab
version.

The dedicated workflow builds CUDA 12.4 / SM86 (RTX A4000), retains CPU fallback
and TLS support, runs synthetic CPU prefill regressions on Windows and packages
the executable with all DLLs, file hashes and source provenance.

Candidate releases are uniquely named prereleases and are not marked latest.
No worker installation, service restart or replacement of the production
`llama-latest-win-cuda.zip` happens in this workflow.

Before rollout, run the candidate in a separate directory and port on one
worker. Compare old/new embeddings on identical input, with unchanged pooling,
then tune microbatch and slot counts separately. Record dimensions, finite
values, vector similarity, throughput, latency and GPU memory. Run the prefill
regressions on the target platform as well. Compile new caches before moving
prefill traffic. Keep a complete binary/DLL/cache rollback set.

This port and its regression tooling were prepared with OpenAI Codex assistance
from the existing NexusAI prefill patch design; no upstream pull request is made.
